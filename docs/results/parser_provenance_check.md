# 解析層抽樣核對：金標對原始財報 HTML 之獨立驗證

**問題**（口試預想質詢）：金標取自二維寬表 CSV，而 CSV 與事實表由同一支 HTML 解析器產出。
若解析器誤讀某儲存格，金標與系統將**一起錯並且彼此對上**，EM 仍為滿分；而 §3.10.1 的機械
稽核係以事實表反查，結構上無法偵測此類錯誤。此為該稽核方法的已知盲區。

**方法**：自 MOPS 原始財報 HTML（`reports_html_copy/`，239 份 inline XBRL 檔）以**獨立解析器**
（BeautifulSoup + lxml，非本系統之 `deal_html_datav2_strip_company_suffix.py`）重新取值。
依（公司集合, 期別集合）分層抽樣 20 題，逐一於原始 HTML 中定位金標所指之
（科目, 期間欄）儲存格，與資料集金標比對；跨公司與跨季度題之複合金標逐分量比對。

## 結果

| 項目 | 數 |
|---|---:|
| 抽樣題數 | 20 |
| 實際比對儲存格 | 33 |
| **一致** | **33** |
| 不一致 | 0 |
| 未能定位／無法對應 | 0 |

**一致率 100.0%（33／33）。**

涵蓋範圍：19 家公司、7 個季度（113Q1, 113Q3, 113Q4, 114Q1, 114Q2, 114Q3, 114Q4）、14 種會計科目，
題目來源橫跨 dev-arch, ho-arch（含 held-out）。

## 解讀

在本次抽樣範圍內，未發現任何一筆金標與原始財報不符，亦即**未觀察到「解析器誤讀導致金標與
系統一起錯」的實例**。這使 §3.10.1 機械稽核的結論在解析層之上獲得一項獨立支持。

**須同時界定其效力**：本檢核為抽樣（33 個儲存格）而非全量，且僅涵蓋三大報表之
數值直查題；關係事實（投資、關係人交易、產業鏈）之金標未納入本次核對，其正確性仍僅由
§3.10.1 之機械稽核與附錄四之 24 題人工核對支持。因此正確陳述為：

> 解析層在三大報表數值題上經 33 個儲存格之獨立抽樣核對，未發現不一致；
> 但機械稽核本身仍無法偵測解析層錯誤，此為方法的結構性邊界而非已消除的風險。
